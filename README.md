# AudioRouter

Formerly SoundTool. The app, Swift package and source directories are now named AudioRouter; audio behavior is unchanged. The existing `app.soundtool.local` bundle identifier and internal audio identifiers are intentionally retained for identity continuity. Older SoundTool bundles remain local historical artifacts; quit any older copy normally before launching AudioRouter. The pre-rename SwiftPM cache and local benchmark evidence are preserved in ignored `.build-before-rename/`; fresh builds use `.build/`.

An independent, local macOS menu-bar audio utility. It does not use SoundSource code, assets, frameworks, identifiers, or licensing. There is no trial period.

### Playback design and limitations

`AudioRoutes` owns the bounded registry and duplicate-process/monitor/teardown policy. Each route reuses a fresh `ProcessMeter` as the sole lifecycle owner of its tap, private tap-only aggregate, capture IOProc, optional `PlaybackSink`, and `SampleTransport`; there is no parallel HAL implementation or shared mutable transport. `TapPlaybackControl` owns description mutation/readback and the obligation to restore original playback; it does not create another tap. Registry identity uses parsed client lifetime snapshots, not app names or bundle ID alone. Duplicate captures of the same PID or HAL object are rejected while owned, including unresolved cleanup. Requested monitor-vs-hardware mode is separate from actual sink readiness, so a partial hardware start is not misclassified as a monitor.

- Input: packed native-endian Float32 stereo PCM, interleaved or planar, 32–96 kHz. Output: native-rate Float32 planar stereo through AUHAL, left/right mapped to the stereo output's two channels. No hardware sample-rate setting or system-default change is made.
- Transport: single producer/single consumer, fixed 16,384-frame stereo FIFO (128 KiB PCM per hardware route; at most 512 KiB across four). The four-owner budget also bounds taps, aggregates, IOProcs, output units and health timers; total HAL/AU memory is host-dependent and unmeasured. Capture and render callbacks use preallocated storage and atomic publication; no locks, UI calls, Tasks or buffer allocation. The main actor polls levels and exclusive-output stream progress at 10 Hz, and HAL identity/format state at 2 Hz. The timer runs in main-run-loop common modes, including menu tracking, without an extra actor Task.
- Timing: approximately 40 ms target FIFO occupancy **plus** capture/device/Bluetooth latency. Nominal rate conversion uses linear interpolation with bounded ±0.5% occupancy-based clock-drift adjustment. **This prototype SRC is not anti-aliased or production-quality.** Audible fidelity, actual latency and drift stability remain unmeasured.
- Backpressure: discard the newest capture packet when full. The consumer discards an excessive backlog to limit latency. Underrun: silence for the remainder of the buffer, then re-prime. Discontinuities may click; no concealment/fade is implemented. Diagnostics expose underrun and dropped-packet counts while open.
- Finite PCM is preserved (including peaks above 1); nonfinite samples become silence. There is no gain/limiter, so source/device clipping remains possible.
- Freshness: revalidate UID, object ID, hardware transport, liveness, sink binding/running state, source/destination formats and client identity every 0.5 seconds. Unknown identity or validation failure stops mirroring. No valid capture callback for three seconds also stops it. The sink is never retargeted to the default output; recovery unsuppresses the app's original playback instead. There is no automatic route reconnect: restart explicitly. Device-change detection is polling, not a sample-accurate guarantee.
- Suppression readiness requires at least 100 ms of PCM delivered to the output callback, capture and output timestamps no older than 0.5 s, no render fault, and at least one second since any underrun. The owner revalidates device/client/format immediately before and after requesting suppression. These are stream-readiness checks, not proof of hardware audibility.
- A new underrun, render error or stale capture/output while suppressed triggers restoration/Stop on the next health poll. HAL identity/permission/format failures do the same. Detection is not instantaneous, and a stalled main thread or blocked modal dialog can delay it; seamless or guaranteed fail-open recovery is **not claimed**.
- `TapPlaybackControl` checks the tap UUID and writability before attempting suppression, preserves other description fields, records a restoration obligation **before** writing, and clears it only after a successful unmuted write and readback. A write error may have taken effect, so it is never treated as proof that playback stayed unmuted.
- Teardown restores unmuted playback **before** disabling transport or stopping capture/sink. If restoration fails, the owner keeps capture/playback resources and retries restoration at 10 Hz when the main run loop is serviced. Dismiss an error dialog to let retries proceed, or use Retry restore / cleanup again. Successful restoration then allows a pending Stop to finish. Callback storage remains owned through successful disposal. Real HAL restoration/cleanup failures remain unverified.

## Build and tests

Requires macOS 15+, Swift 6 and the Apple Command Line Tools. From this directory:

```sh
bash scripts/build-app.sh AudioRouter-0-10-1
# Renamed packaged bundle: 0.10.1, build 17
open build/AudioRouter-0-10-1.app
```

The build script refuses to overwrite an existing bundle. Supply a new build name each time. The app is ad-hoc signed for local use, not notarized.

CLT here lacks XCTest. Run the standalone tests without requesting capture permission, starting a playback device, or changing system audio settings:

```bash
sources=()
for file in Sources/AudioRouter/*.swift; do
  [[ "$file" == */main.swift ]] || sources+=("$file")
done
swiftc -warnings-as-errors -swift-version 6 "${sources[@]}" \
  Tests/AudioRouterTests/*.swift -o .build/audiorouter-tests
.build/audiorouter-tests
```
